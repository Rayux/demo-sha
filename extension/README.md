# Kage browser extension

## Instant first lines

Kage starts preparing subtitles as soon as a Bilibili, YouTube, or Anime1.me video opens, so the first lines exist before you press play. The first 10 seconds are transcribed first (about 1.3 s after audio starts arriving on an M1 Pro), then the rest follows faster than playback while the download continues. Only the tab you are viewing starts; leaving the video stops work Kage started on its own, keeping lines already prepared. Anime1.me no longer needs a play click: Kage asks for the episode source the same way the player does. Turn this off under **Settings → Prepare subtitles as soon as a video opens**. Netflix uses its own Japanese subtitle track and needs no preparation. Reload Kage after updating.

A video Kage starts on its own is checked for Japanese during its first minute. If only another language is heard, Kage stops, removes the lines it made, translates nothing, and does not start that video again by itself. Choose **Download audio & prepare subtitles** to prepare it anyway; that path skips the check. Openings with only music or silence are not counted as another language. Version 1.7.28; run `npm run subtitles:autostart` once when processing is idle so the helper loads the check.

Version 1.7.29: on Bilibili, **Download audio & prepare subtitles** now uses the browser's own audio connection first, as automatic preparation already did, and a page that has just opened waits up to 2 seconds for the player's audio details. The helper's own download, which needs 3 to 4 seconds to look a video up before any audio arrives, is only the fallback. No helper restart is needed.

Version 1.7.30 adds a cover for subtitles embedded in the picture. Hover Kage's subtitle and choose the cover button under the eye to switch it on: a blurred strip appears over the lower part of the video, and Kage's own lines stay above it. Drag the grip at its right end to move it and drag its top edge to change its height (with the grip focused, arrow keys move and Shift + arrow keys resize). Clicks elsewhere on the strip still reach the player. The setting and position are remembered separately for each site.

Version 1.7.31 adds **Settings → Subtitle cover layout** with two choices. **Separate** keeps Kage's subtitle floating above the cover. **On the cover** puts the Japanese and Chinese lines inside the strip, which grows upward when a line needs more room and returns to its set height between lines; the strip's grip then moves both. The glass is now full strength across the middle and fades out over the outer eighth on each side, where embedded subtitles rarely reach.

## Automatic connections

Version **1.7.24** makes **Groq connection → Automatic** the default, including upgrades from the previous VPN toggle. No Settings visit is needed. Kage tries the browser first; if that request receives HTTP 403 or a browser network failure, it tries the local helper through the Mac's own connection. A successful helper connection is remembered for two minutes before trying the browser again. If that remembered helper becomes unreachable, Kage tries the browser immediately. This checks whether the connection works; it does not inspect Urban VPN, browser history, cookies, or proxy settings.

Authentication failures, rate limits, provider server errors, cancellations, and interrupted answer streams do not trigger another route. Manual Browser and Local helper overrides remain in Settings. The helper uses the browser-saved key per request without saving or logging it, streams responses from the fixed Groq endpoint, and requires the existing local token. Keep the helper running. A system-wide VPN or account restriction can still affect its connection. The model remains `openai/gpt-oss-120b`.

YouTube now has one main **Download audio & prepare subtitles** control. It automatically tries the current player's audio connection and falls back to the direct helper downloader if that connection is unavailable or initially refused. Preparation now starts when the video opens (see **Instant first lines**); with that setting off, it waits for a click and native captions continue until then. Existing YouTube media permission is remembered and used automatically, with its optional control under **Settings → YouTube media access (advanced)**. New permission still needs a browser approval once. Bilibili and Netflix keep their existing preparation and caption behavior.

Reload Kage and refresh open video tabs **once to install this update**. VPN toggles afterward need no reload or Settings change. The helper already updated for 1.7.23 requires no further restart. All 401 extension/helper tests pass, covering route changes, helper outages, cancellation, error handling, and YouTube automatic preparation. These fixture tests do not verify a live answer with the user's API key.

## YouTube automatic captions

Version **1.7.22** adds an audio-only SABR downloader for YouTube sessions that play in Brave or Chrome using `POST /videoplayback` and `application/vnd.yt-ump`. Kage uses a locally bundled, pinned [GoogleVideo protocol implementation](vendor/googlevideo/README.md). It reuses the current tab's successful playback context inside that page, downloads audio segments without playing the whole video, and imports only a verified complete audio track into the existing local subtitle helper. Original captions continue normally unless preparation is requested.

Reload Kage, refresh the YouTube tab, briefly initialize playback, pause, then choose **Study → Subtitles → Download audio & prepare subtitles**. Keep the tab open during download. The SABR path uses the page's browser connection, including its existing browser proxy route. It does not export cookies, proxy credentials, playback URLs, or protocol tokens to the helper. Full-file downloads can still use the optional **Settings → YouTube media access (advanced) → Enable YouTube media access** permission. Permission is separate for each browser.

Audio is capped at 128 MiB. Download stops on cancellation, video navigation, timeout, invalid response, unsupported protection/live content, or missing media segments. An independent ledger verifies initialization, sequence, declared bytes and complete duration; a single SABR response ending is never considered a complete download. Current playback/session requirements can still prevent preparation.

A separate FFmpeg decode verified 1420.018 seconds of audio against the player's 23:40 duration, with no decode errors. The helper completed and saved all 478 Japanese lines and 478 Chinese translations; Brave displayed the ready track with no active jobs and playback still paused. This confirms this prepared session; other videos and sessions can have different requirements. The extension/helper suite passes 376 tests, including actual bundled-protocol UMP fixtures, segment gaps, more than 64 segments, cancellation, limits, and native context preservation.

Version **1.7.21** fixes selection of raw low-bitrate metadata links over URLs observed in the player's requests. Successful native fetch/XHR requests rank first, other observed or resource-timing links second, and raw metadata links last. Lower bitrate is considered after this confidence ranking. Captured responses remain bound to the page identity at request start, and their media bodies are never decoded just to observe success.

When an initial download is refused with HTTP 403 or 410, Kage can try up to three distinct eligible media links. Unsigned range/request-counter variations are deduplicated, while different signatures, `n` values, and PO Tokens remain distinct. No token is fabricated or extracted from cookies. Kage never switches candidates after receiving media bytes and stops immediately on HTTP 429. For unknown sizes, one refused range probe may still fall through to an ordinary full request, since a server can refuse probing while allowing a full file.

An HTTP 403 does not establish whether Urban VPN routed the request. It can also reflect a session-bound link or YouTube playback token requirements. The UI now states that uncertainty and reports the number of distinct links attempted instead of implying that reconnecting the VPN is a verified solution. Reload Kage and refresh YouTube to activate this change; the existing optional media permission remains sufficient. The actual Urban-routed video is still unverified without user-run testing.

## Subtitles and furigana

- The player's active native Japanese subtitle normally determines the displayed line. An enabled imported Bilibili track uses the player's playback time directly, including when native subtitles are unavailable. Original text appears immediately. An AI response can enrich only the still-active line; seeks, disappearing captions, disabling, and episode changes invalidate older renders.
- Furigana is always provided by bundled Kuromoji/IPADIC once its dictionary loads. It works offline and does not depend on translation completion, the model, or the optional **AI word meanings** setting. Readings also appear in the panel's selected sentence. Readings are inferred from the transcript, not verified against the video’s pronunciation. Unknown names and ambiguous readings remain dictionary limitations; the extension does not invent missing readings. Dictionary load failures are visible in the Subtitles tab.
- On Netflix, the main-world adapter observes parsed manifest metadata and JSON XHR responses, retaining validated metadata for up to four titles even before entering the watch page. Navigation replays metadata for the exact current title and downloads one Japanese text track and one explicitly identified Traditional Chinese text track when available. It does not change the player's selected language. Simplified Chinese, forced-narrative-only tracks, image-only formats, and other titles are excluded. Native Chinese cues are selected by playback time; cue gaps remain empty rather than repeating an expired translation.
- When no usable native Chinese track is captured, the local model supplies the translation. Check **Study → Subtitles → Translation source** for the actual state. Netflix can change its manifest format or delivery method; live site compatibility is not guaranteed by fixture tests.
- Bilibili can use selectable text subtitles or generate a Japanese track by streaming the current video’s audio, or importing video/audio. Burned-in captions are not read; preparation uses the Japanese audio.

The vendor directory includes kuromoji@0.1.2, its compressed dictionary, copyright notices, and Apache-2.0 license. About 18 MB of dictionary assets are bundled so runtime readings do not send captions to another service. A small documented URL-joining patch preserves Chrome extension resource URLs.

## Background preparation and replay

For local translations, leave Japanese subtitles enabled and play a line so the captured track can be matched to the selected native language. **Next 10 lines** prepares the ten cues after the current position. **Whole track** prepares upcoming dialogue first, then earlier lines in the captured file. The file can be partial if the site delivers segmented subtitles. Keep the tab open and the computer awake; pausing playback lets preparation build a buffer.

**Stop** stops further manual scheduling. The current batch may finish, and normal rolling preloading remains available. Seeking, changing episode, selected track, provider settings, or disabling the extension cancels manual preparation. Reopening/reloading the tab does not automatically restart an unfinished whole-track job; start it again to reuse completed results and continue.

Normal look-ahead covers up to 24 upcoming cues within two minutes and continues through caption gaps once the Japanese track is matched. With **AI word meanings** off, preparation translates up to four lines per model request and sends completed results directly to the page's display cache. Explicit result IDs preserve subtitle alignment. Models that cannot produce a valid batch fall back to individual requests, retaining completed results. AI word meanings retains individual detailed requests.

One local inference runs at a time. Current dialogue can cancel unrelated speculative inference, and obsolete foreground requests are aborted. A current line already in a batch shares its result. Cancelled work never triggers Groq backup; only malformed translation output gets one format retry, while network/authentication failures do not. Tutor requests move ahead of queued subtitle work and cancel unrelated speculative extension preparation. A typed question interrupts the panel’s previous answer. A running foreground subtitle finishes before the tutor starts. The separate local import helper has its own translation queue and can still compete for Ollama while an import is being prepared. Cancellation requests depend on the local server honouring client disconnects.

Batch preparation reduces request overhead; it cannot guarantee zero delay on the first uncached line or when the model translates slower than dialogue arrives. It needs a captured Japanese text track to prepare future lines. The native Chinese track is optional. For dense dialogue on a slow local model, pause and use **Next 10 lines** or **Whole track** to build a buffer.

Completed translations persist in Chrome extension storage, bounded to 8,000 entries or approximately 6 MB. Oldest entries are evicted. Model, endpoint, output mode, fallback setting, target language and text form the cache key. Rewinding reuses a completed translation unless it was evicted or its settings changed. Fast-forwarding beyond prepared lines still requires translation.

The tests cover timing, stale responses, repeated cues, local-only provider routing, cache persistence, batch preparation and ID alignment, cancellation and resumption, subtitle-language changes, navigation/XHR manifest capture, native Chinese timing, and furigana retention. Model requests and Netflix metadata are fixtures; they verify behavior rather than measure real model speed.

`tests/preview.html` is a standalone development fixture with mocked model responses and the real bundled dictionary. Serve the `extension` directory on localhost and open `/tests/preview.html` to review the panel and dictionary loading. It is not loaded by the production manifest.

`tests/import-preview.html` previews the imported-track panel, timing controls, subtitle gaps and editor with a synthetic saved Bilibili track. Model responses are mocked; no media upload or external inference is performed. The service tests use loopback HTTP and a fixture worker; they need permission to listen on localhost.
